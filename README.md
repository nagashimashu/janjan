# 星翠麻雀（SEISUI MAHJONG）

ブラウザーだけで遊べる、一人用の静的Web麻雀ゲームです。
HTML・CSS・Vanilla JavaScript だけで作られており、サーバー・データベース・外部API・外部ライブラリを使いません。GitHub Pages にそのまま公開できます。

> **現在の版：v1.0.0**（全6フェーズ完了）
> 「牌操作デモ」「何切る問題（10問）」「CPU四人麻雀（東風戦・CPUレベル1〜3）」の3モードが遊べます。
> 簡略化しているルールと未実装の機能は、下の「[簡略化したルール](#簡略化したルール)」「[未実装機能](#未実装機能)」に一覧があります。
> 受入条件ごとの確認状況は [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md) にあります。

## ゲーム概要

| モード | 内容 | 推奨端末 |
|---|---|---|
| 牌操作デモ | 配牌・ツモ・選択・打牌・整列・河・ドラ表示など、牌の操作と演出を試す | すべて（縦向き可） |
| 何切る問題 | 14枚から1枚を選び、シャンテン数・受入枚数・受入牌・狙える役・解説で学ぶ（10問） | スマホ縦・PC |
| CPU四人麻雀 | CPU3人と東風戦。鳴き・リーチ・カン・和了・点数計算・流局・順位・戦績保存 | PC・タブレット・スマホ横（縦でも可） |

画面はアニメ調のオリジナルデザインです（深い青緑の卓、金・翡翠・紫のアクセント、半透明パネル、発光・粒子の演出）。牌・エンブレム・効果音もすべて自作です。

## 対応ブラウザー

最新版の Chrome／Edge／Safari／Firefox（PC・タブレット・スマートフォン）。
`<dialog>`、Web Animations API、`dvh` 単位、Pointer Events、CSS `color-mix()` を使用します（2023年以降の主要ブラウザーはすべて対応）。

## 起動方法

1. `index.html` をブラウザーで開く（ビルド不要。ES Modules を使っていないので `file://` でも動きます）
2. または簡易サーバーで確認する（Node.js がある場合）

```bash
node tools/serve.js 8080
```

ブラウザーで `http://localhost:8080/` を開きます。`?debug=1` を付けるとデバッグパネル（牌山のシード、CPUの判断理由など）が表示されます。

## 各モードの説明

### 牌操作デモ

配牌・ツモ・選択・打牌・自動整列・6列の河・残り牌数・巡目・ドラ表示。「手牌読込」で手牌（13枚・14枚）・ツモ順・シードを指定した固定牌山を作れます（表記は `123m456p789s1122z`、0 は赤5）。

### 何切る問題

問題一覧（難易度で絞り込み）→ 牌を選んで「この牌を切る」→ 結果シート。評価は「◎最有力」「○有力」「△目的によって選択可能」「✕改善余地あり」の4段階で、◎と○を正答として数えます。結果シートは「たたむ（評価・シャンテン数・受入枚数・最有力との差）」と「広げる（受入牌と残り枚数・推奨候補・狙える役・解説・判断の観点・全打牌の比較・補足）」の2段階で、手牌は隠れません。回答後に別の牌を押すとその牌を切った場合と比較できます。挑戦数・正答数・正答率を保存します。

**10問すべて、推奨打牌と解説は未レビュー（画面に「確認中」と表示）です。** シャンテン数・受入枚数は計算で検証済みです。

### CPU四人麻雀

対局設定（CPUレベル1〜3、ルールの確認）→ 起家決定（サイコロ）→ 東1局〜東4局。ポン・チー・カン・リーチ・ツモ・ロン・九種九牌、流局（テンパイ判定・ノーテン罰符）、連荘・本場・供託、最終順位。東風戦を最後まで打つと戦績を保存します。

## 操作方法

### 牌の操作（全モード共通）

| 操作 | 動作 |
|---|---|
| 牌をタップ | 選択（牌が浮き上がり、上に▼が付く） |
| 選択中の牌をもう一度タップ | 打牌（打牌方法が「再タップ」のとき） |
| 牌を上へスワイプ | 打牌（小さな動きはタップ扱い。横方向の動きは手牌の横スクロール） |
| 牌を長押し | 牌の名前・赤ドラ・ドラ・ツモ牌などを表示（Iキーでも同じ） |
| 「この牌を切る」 | 選択中の牌を打牌（どの設定でも使えます） |

**誤打牌防止**（既定オン）では、最初のタップ・スワイプは選択だけになります。オフにすると1回で打牌します。

### CPU四人麻雀

| 操作 | 動作 |
|---|---|
| 打牌 | 上と同じ（ツモは自動） |
| 「ツモ」 | 和了形をツモしたときに表示（打牌して続けることもできる） |
| 「ロン」／「スキップ」 | 他家の捨て牌で和了できるときに表示。スキップすると次の自分のツモまでフリテン（リーチ中はその局ずっと） |
| 「リーチ」 | 門前でテンパイになる打牌があるときに表示。押すと切れる牌だけが光るので1枚選ぶ（「リーチ取消」で戻せる）。リーチ後は自動でツモ切り |
| 「ポン」「チー」「カン」 | 鳴けるときに表示。チーの組み合わせ・カンする牌が複数あれば選択画面が出る。自分の番の「カン」は暗槓・加槓 |
| 「九種九牌」 | 最初のツモで么九牌が9種類以上のときに表示（確認のうえ途中流局） |
| 「オート」 | あなたの手番・鳴き・リーチもCPU（レベル2）が判断する |
| メニュー（≡）→「対局を終了」 | 確認のうえ対局をやめる（戦績は保存されない） |

あなたの番になると手牌が光り、短く振動します（振動は設定でオフにできます）。CPUの番は、そのCPUのパネルに「考え中」と表示されます。役がない場合とフリテンの場合はロンのボタンが出ません。

**操作の制限時間**（設定：なし／10秒／20秒／30秒、既定はなし）を付けると、あなたの打牌・鳴きの選択に残り秒数とゲージが表示されます。時間切れになると、打牌はツモ切り（鳴いた直後はツモ牌がないので右端の切れる牌）、鳴き・ロンの選択は見送りになります。残り5秒で色が変わり読み上げで通知しますが、点滅はしません。画面を回転しても残り時間は引き継がれ、画面を離れている間は止まります。

### 設定（`localStorage` に保存）

牌サイズ／打牌方法（再タップ・上スワイプ・確認ボタン）／誤打牌防止／振動／効果音／音量／演出速度（標準・高速・演出少なめ）／CPU思考時間（即時・標準・ゆっくり）／操作の制限時間（なし・10秒・20秒・30秒）／自動整列／ツモ牌を分離表示／横向き推奨表示／デバッグ表示

対局中のメニュー（≡）からは、音量・効果音・振動・演出速度・打牌方法・誤打牌防止・制限時間を変更できます。OS の「視差効果を減らす」（`prefers-reduced-motion`）が有効なときは、移動の演出と粒子を省きます。

## 戦績

「戦績」画面に、この端末のブラウザーに保存した記録を表示します（個人情報は保存しません）。

| モード | 記録する内容 |
|---|---|
| 牌操作デモ | 配牌回数・ツモ回数・打牌回数 |
| 何切る問題 | 挑戦数・正答数・正答率・問題ごとの最高評価と挑戦回数（一覧画面からリセット可） |
| CPU四人麻雀 | 対局数・局数・平均順位・1位率／4位率・順位分布・平均の最終点数・和了率（うちツモ）・放銃率・リーチ率・副露率・CPUレベル別の成績・最高の和了・直近10対局（戦績画面からリセット可） |

CPU四人麻雀の戦績は、東風戦を最後まで打った対局だけを記録します（途中で「対局を終了」した対局・再読み込みで失われた対局は記録しません）。「データ初期化」で設定と全成績を消せます。

## 採用ルール

| 項目 | 設定 |
|---|---|
| 対局 | 東風戦（東4局で親が流れると終了、0点未満でも終了） |
| 持ち点 | 25,000点 |
| 赤ドラ | 5萬・5筒・5索 各1枚 |
| 喰いタン | あり（喰い替え禁止：鳴いた牌と同じ牌、両面で鳴いたときの筋） |
| 和了 | ダブロンなし（頭ハネ）、捨て牌フリテン・同巡内フリテン・リーチ後フリテン |
| 点数計算 | 切り上げ満貫なし、数え役満あり（13翻）、ダブル役満は役満1倍、連風牌の雀頭4符 |
| 本場 | ロン1本300点・ツモ1人100点。親の和了・流局・途中流局で+1、子の和了で0 |
| リーチ | 1,000点・残り4枚以上。一発・裏ドラあり。対局終了時に残った供託はトップ |
| カン | 1局4回まで。カンドラはカンの直後にめくる |
| 流局 | ノーテン罰符 場に3,000点。親がテンパイなら連荘 |
| 途中流局 | 九種九牌（点数移動なし・親は連荘） |
| 操作の制限時間 | 設定で選択（既定なし）。時間切れはツモ切り・見送り |

ルールの値は `data/rules.js`、画面の「ルール設定」で確認できます（変更する画面はありません）。

## 簡略化したルール

牌操作デモ：

- ドラ表示牌は1枚のみ。山は1列の配列として扱い、牌山の積み方・取り出し位置は再現していません

何切る問題：

- 受入は「シャンテン数が進む牌」だけを数えます。好形変化・打点変化は数値に含めず、解説で補っています
- 残り枚数は、手牌14枚・ドラ表示牌・問題文の「見えている牌」だけを差し引きます
- 自分が4枚持っている牌の単騎待ちのような「実際には和了れない聴牌」も、計算上は聴牌として扱います（受入0枚と表示）
- 評価は問題データに書かれたもので、場況の自動評価は行いません。候補に無い打牌はすべて「改善余地あり」です

CPU四人麻雀：

- 途中流局は九種九牌のみです（四風連打・四槓散了・四家立直・三家和は未実装）。ダブル立直・流し満貫・包も未実装です
- カンドラは、明槓・加槓でもカンの直後にめくります
- 和了牌は放銃者の河に残したまま表示します（鳴かれた牌は河から消えます）
- テンパイ判定は「手牌のシャンテン数が0」で行います（純カラもテンパイ扱い）
- 配牌は親から4枚ずつ3巡＋1枚ずつ配りますが、牌山の積み方・開門位置は再現していません（起家決定のみサイコロを使用）
- CPUは和了できるときは必ず和了し、明槓（他家の捨て牌でのカン）はしません。3人とも同じレベルです
- 役：二盃口は未実装（一盃口が2組でも一盃口1翻）。未実装の役満の形は、成立する通常役で計算します
- 対局は画面を再読み込みすると失われます（画面回転・ほかの画面への移動では失われません）

## 問題追加方法

問題は `data/questions.js` の `MJ.QUESTIONS` に追加します。手順は [skills/add-question.skill.md](skills/add-question.skill.md) を参照してください。

```bash
node tools/question-tool.js --hand 23456m78p345678s4z --dora 1p
```

で任意の手牌の全打牌（シャンテン数・受入）を出力できます。候補の数値は手で数えず、この出力を使ってください。`node tools/question-tool.js` で全問題を検証できます（テストでも同じ検証を行います）。問題には必ず `reviewed`・`reviewerNote`・`lastUpdated` を付け、未レビューの問題は画面に「確認中」と表示します。

## 役追加方法

役は `js/yaku.js` の `YAKU` 配列に定義を1つ追加します（翻数・副露時の翻数・対象の和了形・複合しない役・判定関数）。手順は [skills/add-yaku.skill.md](skills/add-yaku.skill.md) を参照してください。必ず `tests/specs/yaku.spec.js` と `tests/specs/scoring.spec.js` にテストを追加してください。

## CPU評価ロジック

`js/cpu-player.js` にあります。対局設定画面でレベル1〜3を選べます（既定はレベル2、3人とも同じレベル）。

| レベル | 内容 |
|---|---|
| 1 | シャンテン数を悪化させない牌だけを候補にし、その中で「残す価値」が最も低い牌を切る。残す価値＝他の牌とのつながり（同じ牌・隣・1つ飛び）＋数牌の位置（3〜7＞2・8＞1・9）＋字牌の評価（役牌は少し高く、オタ風は低く）。和了できるときは必ず和了する。リーチ・鳴きはしない |
| 2 | シャンテン数を最優先し、同じなら受入枚数（見えている牌を除いた残り枚数）が多い牌を残す。ドラ・赤ドラ・役牌の対子を切ると減点。テンパイで待ちが残っていればリーチ（待ちの残りが最も多い牌で）。鳴きは「役が確定し（役牌・喰いタン・混一色）、シャンテン数が進む」ときだけ（役牌の対子はポン）。暗槓・加槓は形を崩さなければする。九種九牌は么九牌11種以上なら国士無双を狙う |
| 3 | レベル2に加えて、リーチ者がいるときは押し引きを判断：テンパイなら押す、1シャンテンは残り30枚以上なら押す、それ以外は降りる（オーラスのトップは早めに降り、ラスは2シャンテンまで押す）。降りるときは危険度が最も低い牌を切る（現物0、字牌は見えている枚数で、数牌は端ほど安全・筋（片筋）・壁で減らす）。押すときも危険度を加味。打点（ドラ・役牌）をレベル2より重く見る。リーチ者がいるときはカンしない |

判断理由と評価値（0〜100、大きいほど「切ってよい」）はデバッグパネル（`?debug=1` または設定の「デバッグ表示」）に表示されます。

```text
CPU南（アカネ）：北を選択　理由：シャンテン数維持、孤立牌、役のない字牌　評価値：100
CPU南（アカネ）：北を選択　理由：リーチ者がいるため降り、現物　評価値：100
```

## GitHub Pages への公開

1. `mahjong-web` フォルダーの中身をリポジトリのルートに置いてプッシュする
2. GitHub のリポジトリで **Settings → Pages** を開く
3. **Source** を「Deploy from a branch」、ブランチを `main`、フォルダーを `/ (root)` にして保存
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

ビルド処理はありません。すべて相対パスで参照しているため、サブパスでも動作します。`.nojekyll` を置いているので、GitHub Pages の Jekyll 処理は行われません。公開前のチェック項目は [skills/pre-release-check.skill.md](skills/pre-release-check.skill.md) にあります。

## 著作権・素材方針

- 牌面（SVG）・エンブレム・背景・配色・画面構成・プレイヤー名は、すべて本プロジェクトのオリジナルです
- 効果音は Web Audio API で合成しており、音声ファイルは使用していません
- 既存の麻雀ゲームの画面・ロゴ・名称・キャラクター・牌画像・効果音・台詞は使用していません
- 外部画像・外部フォント・外部ライブラリは使用していません（牌の漢字は端末の明朝体で描画します）
- 保存するのは設定と成績だけで、個人情報は収集しません
